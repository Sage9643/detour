# Development Log

Chronological record of what was done, what was verified, and what was learned.
Only measured facts go here.

## 2026-10-05: Phase 0 (design review)
Design review accepted. Key outcomes: gated utility followed by MMR instead of a 3-term
weighted sum; exploratory retrieval (bridge and adjacent queries); a GitHub-stars
temporal split for offline evaluation; evaluation harness moved forward to Phase 4.
Clarified requirement: no learned model unless data and an experiment justify one; the
schema must support one later.

## 2026-10-05: Phase 1 (foundation)

**Built:** project layout, env-based config, app factory with liveness and readiness,
6-table schema with Alembic migration `0001`, docker-compose for Postgres, CI workflow,
specification docs.

**Environment note:** The development workspace could not pull Docker Hub images
(registry blocked by network policy). Verification therefore used a native
PostgreSQL 16.15 server. `docker compose config` validated the compose file, but **the
container was not booted** in this environment.

**Verified (commands in README):**
- ruff lint and format check: pass. mypy `--strict`: no issues (13 source files).
- `alembic upgrade head` → `0001`. `alembic check`: "No new upgrade operations detected".
  Downgrade to base and upgrade again: pass.
- pytest: **51 passed** on Python 3.13.16, and **51 passed** on Python 3.12.3 while
  replaying all CI steps against a fresh database.
- `uvicorn` boot: `/health` → 200; `/health/ready` → 200 with `schema_revision: "0001"`.
  Missing `DATABASE_URL` → startup fails with a pydantic validation error.
- `actionlint` on the workflow: no issues.

**Lessons:**
- Autogenerated migrations need review: the draft created an index on
  `interests.user_id` that duplicated the leading column of the unique
  `(user_id, lower(label))` index. Removed.
- Starlette now deprecates plain `httpx` for `TestClient`; switched the dev dependency
  to `httpx2`.
